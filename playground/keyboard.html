Keyboard

Everything a pointer does, the keyboard does too. Keys work while the wave has focus, and never take a key held with Ctrl, Alt or ⌘, which belong to the browser and the page.

The wave

The keys of the WAI-ARIA slider pattern:

  • ← → ↑ ↓ step by stepSeconds (5 seconds)
  • Page Up Page Down step by largeStepRatio (a tenth of the sound)
  • Home End go to the start and the end

Press Tab until the wave above is focused, and try the keys on this page.

Zoom

With zoom: { keys: true }:

  • + (or =) zooms in, - zooms out, 0 shows the whole sound
  • A key seek outside the view brings the view to it (revealKeys, on by default)

keys: { in: 'i', out: 'o', reset: false } picks other keys or turns one off.

Markers

  • M goes to the next marker, Shift + M to the previous one
  • Within backGrace seconds after a marker (1), Shift + M goes to the one before it, like a player's "previous track"

Regions

  • R and Shift + R select the next and previous region
  • Enter plays it, L loops it, Delete removes it
  • [ ] move its start, { } move its end

The wave in words

With description: { keys: true }:

  • D says the description again
  • P and Shift + P go to the next and previous part of sound, and say where ("Part 2 of 3, 24 seconds")
  • Escape stops the browser's voice while it reads

The minimap and the volume

Both are sliders too. The minimap (with a11y.minimap.keys): arrows move a quarter of the view, Page Up and Page Down a whole view, Home and End go to the ends. The volume bar: arrows by step (5 %), Page Up and Page Down by a tenth, Home and End to silent and full.

Caps Lock changes nothing

The direction comes from Shift, never from the letter's case, so M, R and P work the same with Caps Lock on.
