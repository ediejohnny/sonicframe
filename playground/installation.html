Installation

One package, no dependencies, three entry points. Install it with your package manager, load it straight from a CDN, or build it from its source code.

With a package manager

SonicFrame is published on npm as sonicframe. Use whichever manager your project already uses: 

npm install sonicframe
pnpm add sonicframe
yarn add sonicframe
bun add sonicframe

It brings nothing else along: the published package has no runtime dependencies and no install scripts. Types come in the package, so TypeScript needs nothing extra.

Three entry points

Import only what the page needs. An app that draws waves never loads the ready-made player, and a server that reads peaks never loads anything that touches the DOM.

Import What is in it Use it for
sonicframe The frame (SonicFrame), every plugin, the play button, the volume control, the peaks readers and the analysis functions. Building your own player, or drawing waves with your own controls.
sonicframe/player createPlayer, the themes and palettes, and the <sonic-player> tag. A complete player in one call or one tag.
sonicframe/analysis Pure functions: levels, silences, the wave in words, and the waveform file writer. Servers, workers and build scripts (Node, Deno, Bun). 
import { SonicFrame, loadPeaks } from 'sonicframe';
import { createPlayer } from 'sonicframe/player';
import { writeWaveform } from 'sonicframe/analysis';

From a CDN

No build step? Any npm CDN serves the package as plain modules. Pin the version you tested: 

<script type="module">
    import { createPlayer } from 'https://cdn.jsdelivr.net/npm/sonicframe@0.4.0/dist/player.js';

    createPlayer({
        container: document.querySelector('#player'),
        src: '/voice.mp3',
    });
</script>
Tip A strict Content-Security-Policy keeps working: add the CDN to script-src, and nothing else is needed. SonicFrame sets no inline styles, runs no eval and starts no blob workers.

From the source code

Rather not use a package manager in your project? Build SonicFrame from its source once and copy the result into your site. Your site then loads plain files of its own, and nothing from npm goes into it.

To build, you need Node.js 22 (22.18 or later), 24 (24.11 or later) or 26 and up. Git is optional. Node brings npm along, which only fetches the build tools into the source folder.

1. Get the code

Clone the version you want, by its tag:

git clone --depth 1 --branch v0.4.1 https://github.com/ediejohnny/sonicframe.git
cd sonicframe

No Git? Open the project's tags on GitHub, download the zip of the version and unzip it.

2. Build it

npm ci
npm run build

npm ci installs the exact build tools the project pins, inside its folder. npm run build writes the library to dist/. To see the tests pass first, run npm test.

3. Copy the files into your site

Copy the whole dist/ folder into your site, with the LICENSE file next to it (the MIT license asks to keep its notice with the code); for example, as vendor/sonicframe/. Keep the folder whole: the entry files import shared pieces whose names change with every build.

4. Import it

Import the files by their path:

<div id="player"></div>

<script type="module">
    import { createPlayer } from './vendor/sonicframe/player.js';

    createPlayer({
        container: document.querySelector('#player'),
        src: '/voice.mp3',
    });
</script>

To keep the imports these docs use, such as 'sonicframe/player', add an import map before your first module: 

<script type="importmap">
{
    "imports": {
        "sonicframe": "/vendor/sonicframe/index.js",
        "sonicframe/player": "/vendor/sonicframe/player.js",
        "sonicframe/analysis": "/vendor/sonicframe/analysis.js"
    }
}
</script>
With a strict Content-Security-Policy An import map is an inline script, so script-src needs its hash ('sha256-…'). Imports by path, from your own module files, need nothing more.

With TypeScript, point the names at the types in the folder: 

{
    "compilerOptions": {
        "paths": {
            "sonicframe": ["./vendor/sonicframe/index.d.ts"],
            "sonicframe/player": ["./vendor/sonicframe/player.d.ts"],
            "sonicframe/analysis": ["./vendor/sonicframe/analysis.d.ts"]
        }
    }
}

Updating

Get the new version's tag, build again and replace the whole folder. The changelog says what changed.

Module format

SonicFrame is shipped as standard ES modules ("type": "module"), compiled for ES2022. Every current bundler (Vite, webpack, Rollup, esbuild, Parcel) and every current browser loads it as is. There is no CommonJS build; in Node, use import (or a dynamic import() from CommonJS).

The package is marked free of side effects, so a bundler drops every plugin and function you do not import.
