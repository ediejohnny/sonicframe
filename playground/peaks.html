Peaks

Peaks are the loudest point of each slice of a sound, as numbers from 0 to 1. They are all the frame needs to draw: SonicFrame never decodes audio just to draw it.

The idea

Compute the peaks once, when a sound is uploaded, and serve them as a small file. A few hundred to a few thousand values are plenty: the frame folds or stretches them to the number of bars that fit.

A peaks file is either a list or an object with a list: 

[0.02, 0.31, 0.77, 0.54, 0.12]
{ "peaks": [0.02, 0.31, 0.77, 0.54, 0.12] }

Giving peaks to a frame

peaks takes any of these:

Value What happens
a list of numbers drawn at once.
{ peaks, duration } drawn at once; the duration shows until the media knows its own.
a function returning a promise of either called the first time the frame comes near the screen.
null a thin line until peaks arrive (setPeaks). 
import { SonicFrame, loadPeaks } from 'sonicframe';

new SonicFrame({
    container,
    media,
    peaks: () => loadPeaks('/voice.peaks.json'),
});

loadPeaks(url) fetches a file once per page, however many frames use it, and refuses a file with more than 20,000 values. For larger and binary files, use ready-made waveform files.

Making peaks

On your server

Write an audiowaveform file with writeWaveform from sonicframe/analysis (it runs in Node), or use the audiowaveform tool itself. Both are covered in Ready-made peaks.

In the browser

For a recording just made, compute them from the decoded samples: 

import { peaksFromChannel } from 'sonicframe';

const peaks = peaksFromChannel(audioBuffer.getChannelData(0), 400);

Let the player do it

The ready-made player, given only src, decodes the sound in the browser the first time it comes near the screen. It is the easiest start, and the most expensive for long sounds; decode on the player sets its limits.

Shape, not loudness

Peaks are relative: a quiet recording and a loud one can draw the same wave. The bar style's curve (0.7 by default) lifts quiet parts so speech reads well; 1 draws the peaks as they are. See Drawings.
