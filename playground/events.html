Events

on(event, listener) listens and gives back the function that stops listening. Events never fire once per animation frame, so listening is cheap.

Listening

const stop = frame.on('timeupdate', (time, ratio) => {
    clock.textContent = formatTime(time);
});

// Later:
stop();

The player has the same on, with every frame event plus description; the <sonic-player> tag dispatches them as DOM events named sonicframe:seek, sonicframe:timeupdate and so on, with the arguments in event.detail.

Every event

Event Arguments When
seek { ratio, time, source } A click, a drag, a key or seekTo moved the position.
hover ratio, time The mouse moved over the wave (null when it left).
timeupdate time, ratio The media moved, at its own pace.
durationchange duration The length became known or changed.
peakschange peaks The peaks arrived, were replaced or went.
resize geometry The wave changed size, or a lazy frame got its pixels.
rangeend A range being played ended or was abandoned.
viewchange view, source The view moved (zoom on), and what moved it.
error error Loading peaks or a plugin's work failed.
destroy The frame was destroyed.

Errors never break the page

A failed download, a plugin that throws, a peaks file that does not parse: each one reaches the error event, and the rest of the frame keeps working. A plugin that throws is parked, so one broken plugin never breaks the wave. 

frame.on('error', (error) => report(error));
