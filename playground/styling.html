Colors and CSS

Every color SonicFrame draws can come from your CSS. Set a few custom properties on any ancestor, and the waves, the buttons and every plugin follow, dark mode included.

Theming with custom properties

:root {
    --sonicframe-wave: #c4cad4;
    --sonicframe-progress: #1f4fbf;
}

@media (prefers-color-scheme: dark) {
    :root {
        --sonicframe-wave: #3d4b60;
        --sonicframe-progress: #8fb6ff;
    }
}

The system's light and dark switch is followed on its own. If your site switches with a class instead, call frame.refresh() (or the player's frame.refresh()) after the switch: canvas colors are read once, not every frame.

Colors in code

colors takes any CSS color or var(--name, fallback):

Color Default Used for
wave var(--sonicframe-wave, #c4cad4) Bars not yet played.
progress var(--sonicframe-progress, #2f6fdb) Bars already played.
hover 'auto' The band between the played part and the pointer (null shows none).
cursor null A line at the playing position.
waveHover, progressHover null Recolor the bars while the pointer is over the wave ('auto' nudges them).
knob null The dot riding the position (takes progress).

The focus ring

The wave is a focusable slider. Style its focus with :focus-visible on your container: 

#wave:focus-visible {
    outline: 2px solid var(--sonicframe-progress);
    outline-offset: 2px;
}

The player's buttons draw their own ring for the keyboard, one line in the played color: on a button with a border it takes the border's place, and on one without it sits 2 px out, where the button's own fill cannot hide it.

Safe colors

Colors only ever reach properties that accept nothing but a color (the canvas, background-color, color, border), so a color from a user or a database can never make the page fetch an address. Variables are resolved in linear time, at most eight levels deep.

Every property, with what it paints, is in CSS variables.
